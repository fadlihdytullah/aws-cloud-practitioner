<Section num="01" id="intro" title="Apa itu S3?" sub="Penyimpanan objek untuk hampir semua kebutuhan digital">

<p class="lead">
  Amazon S3 (Simple Storage Service) adalah layanan penyimpanan objek yang
  dipakai untuk menyimpan file, backup, log, gambar, video, data lake, file
  website statis, dan banyak skenario lain.
</p>

Bayangkan S3 seperti gudang digital yang sangat besar. Kita tidak mengelola server penyimpanan, tidak memasang disk sendiri, dan tidak perlu memikirkan kapasitas awal. Kita cukup membuat <em class="term">bucket</em>, lalu memasukkan <em class="term">object</em> ke dalamnya.

<Figure>
  <S3Fig01 />
  <Fragment slot="caption">
    <b>Gambar 1.</b> Relasi sederhana antara aplikasi, bucket, object, keamanan,
    dan lifecycle di Amazon S3.
  </Fragment>
</Figure>

<CardGrid cols={3}>
  <Card>
    <h4>Durable</h4>
    <p>
      S3 dirancang untuk menyimpan data dengan ketahanan sangat tinggi. Cocok
      untuk data penting seperti backup, arsip, dan aset aplikasi.
    </p>
  </Card>
  <Card>
    <h4>Scalable</h4>
    <p>
      Kita tidak perlu menentukan ukuran disk. Bucket dapat menampung object
      dalam jumlah besar dan bertumbuh sesuai kebutuhan.
    </p>
  </Card>
  <Card>
    <h4>Object storage</h4>
    <p>
      S3 menyimpan data sebagai object, bukan block storage seperti EBS dan
      bukan file system tradisional seperti EFS.
    </p>
  </Card>
</CardGrid>

<Box variant="analogy" icon="📦" label="Analogi sederhana">
  <p>
    Jika EBS seperti hard disk yang ditempel ke satu EC2, S3 seperti gudang
    paket online. Setiap paket punya nama, label metadata, dan alamat unik untuk
    ditemukan kembali.
  </p>
</Box>

<Box variant="exam" icon="🎯" label="Fokus ujian">
  <p>
    Untuk CLF-C02, pahami kegunaan S3, keamanan dasar, storage class, enkripsi,
    versioning, dan shared responsibility. Untuk SAA-C03, pahami pilihan
    arsitektur seperti replication, lifecycle, static website, dan integrasi
    transfer data.
  </p>
</Box>

</Section>

<Section num="02" id="bucket-dan-object" title="Bucket dan Object" sub="Dua istilah paling penting di S3">

<p class="lead">
  S3 memakai dua konsep utama, bucket sebagai wadah, dan object sebagai file
  yang disimpan di dalam bucket.
</p>

Bucket adalah container tingkat atas. Nama bucket harus unik secara global, karena nama tersebut menjadi bagian dari alamat akses S3. Object adalah data yang kita simpan, misalnya `foto.jpg`, `invoice.pdf`, `backup.zip`, atau `logs/2026/06/app.log`.

<CardGrid cols={2}>
  <Card>
    <h4>Bucket</h4>
    <p>
      Wadah penyimpanan dengan nama unik global. Bucket dibuat di region
      tertentu, misalnya Asia Pacific (Singapore), US East (N. Virginia), atau
      Europe (Ireland).
    </p>
  </Card>
  <Card>
    <h4>Object</h4>
    <p>
      Isi bucket yang terdiri dari data, key, metadata, dan versi jika
      versioning diaktifkan. Key terlihat seperti path, tetapi S3 tetap object
      storage.
    </p>
  </Card>
</CardGrid>

<h3>Key bukan folder sungguhan</h3>

Di console S3, kita melihat struktur seperti folder, misalnya `assets/images/logo.png`. Secara teknis, object key adalah string panjang. Folder hanyalah cara console menampilkan prefix agar manusia lebih mudah memahami struktur data.

<Box variant="tip" icon="💡" label="Cara mengingat">
  <p>
    Bucket adalah nama lemari. Object adalah barang di dalam lemari. Key adalah
    label lokasi barang, misalnya <code>dokumen/kontrak.pdf</code>.
  </p>
</Box>

<h3>URL dan akses</h3>

Object di S3 bisa memiliki URL, tetapi belum tentu bisa diakses publik. Secara default, S3 mendorong praktik private by default. Akses diberikan lewat IAM policy, bucket policy, access point, pre-signed URL, atau pengaturan lain yang sengaja dibuat.

</Section>

<Section num="03" id="hands-on-dasar" title="Hands On Dasar S3" sub="Alur praktik membuat bucket dan mengunggah object">

<p class="lead">
  Pada praktik dasar, tujuan utamanya adalah memahami alur membuat bucket,
  upload file, melihat object, dan mengatur akses dengan hati-hati.
</p>

<Steps>
  <Step>
    <b>Buat bucket</b>
    <p>
      Pilih nama bucket yang unik global, pilih region yang dekat dengan user
      atau sesuai kebutuhan compliance, lalu biarkan pengaturan block public
      access tetap aktif untuk awal.
    </p>
  </Step>
  <Step>
    <b>Upload object</b>
    <p>
      Unggah file kecil seperti gambar atau dokumen. Amati object key, size,
      storage class, dan metadata yang muncul di console.
    </p>
  </Step>
  <Step>
    <b>Uji akses</b>
    <p>
      Coba buka object URL. Jika bucket masih private, akses akan ditolak. Ini
      normal dan justru merupakan pengaturan aman.
    </p>
  </Step>
  <Step>
    <b>Atur izin hanya bila perlu</b>
    <p>
      Gunakan bucket policy, IAM policy, atau pre-signed URL sesuai skenario.
      Jangan membuka bucket publik tanpa alasan jelas.
    </p>
  </Step>
</Steps>

<Box variant="warn" icon="⚠️" label="Kesalahan pemula">
  <p>
    Jangan menganggap upload file berarti file otomatis publik. Di S3 modern,
    akses publik harus dibuat dengan sengaja dan sebaiknya hanya untuk skenario
    seperti website statis atau aset publik tertentu.
  </p>
</Box>

<h3>Kapan memakai S3?</h3>

S3 cocok untuk menyimpan file yang tidak perlu diperlakukan sebagai disk sistem operasi. Contoh umum adalah gambar produk, dokumen pengguna, file export laporan, backup database, data mentah untuk analitik, log aplikasi, dan konten website statis.

</Section>

<Section num="04" id="keamanan-bucket-policy" title="Keamanan S3 dan Bucket Policy" sub="Siapa boleh melakukan apa, pada resource mana">

<p class="lead">
  Keamanan S3 berpusat pada kontrol akses. Kita menentukan siapa yang boleh
  membaca, menulis, menghapus, atau mengelola object dan bucket.
</p>

Ada beberapa lapisan izin di S3. IAM policy biasanya melekat pada user, group, atau role. Bucket policy melekat pada bucket. Access Control List (ACL) adalah mekanisme lama dan umumnya dihindari jika tidak diperlukan. Block Public Access adalah pagar pengaman agar bucket tidak terbuka publik secara tidak sengaja.

<Figure>
  <S3Fig02 />
  <Fragment slot="caption">
    <b>Gambar 2.</b> Lapisan keamanan umum di S3, dari identitas sampai
    guardrail publik.
  </Fragment>
</Figure>

<CardGrid cols={2}>
  <Card>
    <h4>IAM policy</h4>
    <p>
      Mengatur izin dari sisi identitas. Contoh, role aplikasi boleh membaca
      object di bucket tertentu.
    </p>
  </Card>
  <Card>
    <h4>Bucket policy</h4>
    <p>
      Mengatur izin dari sisi resource. Contoh, bucket mengizinkan CloudFront
      OAC membaca object tertentu.
    </p>
  </Card>
  <Card>
    <h4>Block Public Access</h4>
    <p>
      Guardrail untuk mencegah akses publik. Sangat penting untuk mencegah
      kebocoran data karena salah konfigurasi.
    </p>
  </Card>
  <Card>
    <h4>Pre-signed URL</h4>
    <p>
      URL sementara untuk memberi akses terbatas waktu ke object private,
      misalnya link unduh invoice selama 10 menit.
    </p>
  </Card>
</CardGrid>

<h3>Contoh pola bucket policy</h3>

Contoh berikut menunjukkan bentuk JSON secara konsep. Perhatikan bahwa kurung kurawal perlu di-escape di MDX agar tidak dianggap ekspresi JavaScript.

<pre>
  <code>
    &#123; "Version": "2012-10-17", "Statement": [ &#123; "Effect": "Allow",
    "Principal": "*", "Action": "s3:GetObject", "Resource":
    "arn:aws:s3:::nama-bucket/*" &#125; ] &#125;
  </code>
</pre>

<Box variant="warn" icon="🔒" label="Hati-hati">
  <p>
    Policy di atas membuka baca object untuk publik. Gunakan hanya untuk konten
    yang memang publik, misalnya aset website statis. Untuk data private,
    gunakan IAM role, CloudFront dengan Origin Access Control, atau pre-signed
    URL.
  </p>
</Box>

<Box variant="exam" icon="🎯" label="Kata kunci ujian">
  <p>
    Jika pertanyaan menyebut akses sementara ke object private, jawabannya
    sering mengarah ke pre-signed URL. Jika menyebut mencegah bucket terbuka
    publik, ingat Block Public Access.
  </p>
</Box>

</Section>

<Section num="05" id="static-website" title="S3 Static Website Hosting" sub="Menjalankan website HTML, CSS, dan JavaScript tanpa server">

<p class="lead">
  S3 dapat menjadi host untuk website statis, yaitu website yang terdiri dari
  file seperti HTML, CSS, JavaScript, gambar, dan aset lain tanpa backend server
  yang berjalan di S3.
</p>

Website statis cocok untuk landing page, dokumentasi, portfolio, halaman marketing, atau build frontend seperti React yang sudah menjadi file statis. Untuk aplikasi modern, S3 sering dipasangkan dengan CloudFront agar lebih cepat, lebih aman, dan bisa memakai HTTPS dengan mudah.

<Steps>
  <Step>
    <b>Aktifkan static website hosting</b>
    <p>
      Di pengaturan bucket, aktifkan fitur website hosting dan tentukan index
      document seperti <code>index.html</code>.
    </p>
  </Step>
  <Step>
    <b>Upload file website</b>
    <p>
      Unggah hasil build, misalnya <code>index.html</code>, file CSS,
      JavaScript, gambar, dan asset lain.
    </p>
  </Step>
  <Step>
    <b>Atur akses publik atau CloudFront</b>
    <p>
      Untuk demo sederhana, bucket policy publik bisa digunakan. Untuk produksi,
      CloudFront lebih direkomendasikan.
    </p>
  </Step>
  <Step>
    <b>Uji endpoint website</b>
    <p>
      Gunakan endpoint website S3, bukan object URL biasa. Endpoint website
      berbeda dari endpoint REST S3.
    </p>
  </Step>
</Steps>

<Box variant="tip" icon="🌐" label="Frontend developer note">
  <p>
    Untuk React, Laravel mix asset, atau dokumentasi statis, S3 dapat menyimpan
    hasil build. Jika butuh routing SPA seperti <code>/dashboard</code>,
    biasanya perlu konfigurasi error document atau CloudFront function sesuai
    kebutuhan.
  </p>
</Box>

<Box variant="exam" icon="🎯" label="Fokus ujian">
  <p>
    S3 static website hosting tidak menjalankan kode server-side. Jika aplikasi
    butuh backend dinamis, gunakan layanan lain seperti EC2, Lambda, Elastic
    Beanstalk, ECS, atau API Gateway.
  </p>
</Box>

</Section>

<Section num="06" id="versioning" title="S3 Versioning" sub="Menyimpan riwayat perubahan object">

<p class="lead">
  S3 Versioning menyimpan beberapa versi dari object yang sama, sehingga
  perubahan dan penghapusan bisa dipulihkan dalam banyak skenario.
</p>

Saat versioning aktif, upload object dengan key yang sama tidak benar-benar menimpa versi lama. S3 membuat versi baru. Jika object dihapus, S3 dapat menambahkan delete marker, sehingga versi lama masih dapat ditemukan dan dipulihkan.

<CardGrid cols={2}>
  <Card>
    <h4>Melindungi dari overwrite</h4>
    <p>
      Jika file diganti tidak sengaja, versi sebelumnya masih ada dan dapat
      dipulihkan.
    </p>
  </Card>
  <Card>
    <h4>Melindungi dari delete</h4>
    <p>
      Delete marker membuat object terlihat terhapus, tetapi versi lama masih
      bisa diakses jika kita melihat daftar versi.
    </p>
  </Card>
</CardGrid>

<Box variant="warn" icon="💸" label="Dampak biaya">
  <p>
    Versioning dapat meningkatkan biaya karena versi lama tetap disimpan.
    Gunakan lifecycle rule untuk membersihkan versi lama sesuai kebutuhan
    bisnis.
  </p>
</Box>

<h3>Versioning dan MFA Delete</h3>

MFA Delete dapat menambah proteksi untuk operasi penghapusan versi object, tetapi penggunaannya lebih khusus. Untuk ujian dasar, cukup pahami bahwa versioning membantu pemulihan dari overwrite dan delete yang tidak disengaja.

</Section>

<Section num="07" id="replication" title="S3 Replication" sub="Menyalin object ke bucket lain secara otomatis">

<p class="lead">
  S3 Replication menyalin object dari satu bucket ke bucket lain secara
  otomatis, biasanya untuk kebutuhan compliance, disaster recovery, atau
  kedekatan geografis.
</p>

Ada dua pola utama, Cross-Region Replication (CRR) untuk menyalin ke region berbeda, dan Same-Region Replication (SRR) untuk menyalin di region yang sama. Versioning harus aktif pada bucket sumber dan tujuan.

<Figure>
  <S3Fig03 />
  <Fragment slot="caption">
    <b>Gambar 3.</b> Contoh replikasi S3 lintas region untuk kebutuhan disaster
    recovery dan compliance.
  </Fragment>
</Figure>

<CardGrid cols={2}>
  <Card>
    <h4>CRR</h4>
    <p>
      Menyalin object ke bucket di region lain. Cocok untuk disaster recovery,
      compliance geografis, dan latensi baca dari lokasi berbeda.
    </p>
  </Card>
  <Card>
    <h4>SRR</h4>
    <p>
      Menyalin object ke bucket lain dalam region yang sama. Cocok untuk
      pemisahan akun, agregasi log, atau aturan keamanan berbeda.
    </p>
  </Card>
</CardGrid>

<Box variant="exam" icon="🎯" label="Syarat penting">
  <p>
    Ingat bahwa replication membutuhkan versioning pada bucket sumber dan bucket
    tujuan. Object lama sebelum rule dibuat tidak otomatis direplikasi kecuali
    memakai batch replication.
  </p>
</Box>

<h3>Apa yang biasanya direplikasi?</h3>

Object baru setelah rule aktif dapat direplikasi. Kita bisa menentukan prefix atau tag tertentu agar hanya sebagian object yang disalin. S3 juga mendukung pilihan seperti replikasi metadata, object lock, dan replication time control untuk kebutuhan yang lebih ketat.

</Section>

<Section num="08" id="storage-classes" title="S3 Storage Classes" sub="Memilih kelas penyimpanan sesuai pola akses">

<p class="lead">
  S3 Storage Classes membantu kita menyeimbangkan biaya, durabilitas,
  ketersediaan, dan waktu akses berdasarkan seberapa sering data dipakai.
</p>

Tidak semua data perlu disimpan di kelas yang sama. File yang sering diakses cocok di S3 Standard. Arsip yang jarang sekali dibuka cocok di Glacier class. Data yang tidak tahu polanya bisa memakai Intelligent-Tiering.

<table>
  <thead>
    <tr>
      <th>Storage class</th>
      <th>Kapan dipakai</th>
      <th>Catatan ujian</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>S3 Standard</td>
      <td>Data sering diakses</td>
      <td>Default, high availability, low latency</td>
    </tr>
    <tr>
      <td>S3 Intelligent-Tiering</td>
      <td>Pola akses tidak pasti</td>
      <td>Memindahkan data antar tier secara otomatis dengan monitoring fee</td>
    </tr>
    <tr>
      <td>S3 Standard-IA</td>
      <td>Jarang diakses, tetapi harus cepat saat dibuka</td>
      <td>Biaya storage lebih rendah, ada retrieval fee</td>
    </tr>
    <tr>
      <td>S3 One Zone-IA</td>
      <td>Jarang diakses dan dapat dibuat ulang</td>
      <td>
        Disimpan di satu Availability Zone, lebih murah tetapi risiko lebih
        tinggi
      </td>
    </tr>
    <tr>
      <td>S3 Glacier Instant Retrieval</td>
      <td>Arsip jarang diakses tetapi perlu akses milidetik</td>
      <td>Cocok untuk arsip yang harus cepat dibaca</td>
    </tr>
    <tr>
      <td>S3 Glacier Flexible Retrieval</td>
      <td>Arsip dengan waktu pengambilan menit sampai jam</td>
      <td>Lebih murah untuk data arsip yang tidak perlu langsung tersedia</td>
    </tr>
    <tr>
      <td>S3 Glacier Deep Archive</td>
      <td>Arsip jangka panjang yang sangat jarang dibuka</td>
      <td>Biaya storage sangat rendah, retrieval paling lama</td>
    </tr>
  </tbody>
</table>

<Box variant="analogy" icon="🗄️" label="Analogi gudang">
  <p>
    S3 Standard seperti rak depan toko yang sering diambil. Standard-IA seperti
    gudang belakang. Glacier seperti arsip di depo, murah untuk disimpan, tetapi
    perlu proses saat ingin mengambilnya.
  </p>
</Box>

<h3>Lifecycle rules</h3>

Lifecycle rules dapat memindahkan object ke storage class lebih murah setelah umur tertentu, atau menghapus object dan versi lama secara otomatis. Contoh, log aplikasi disimpan di Standard selama 30 hari, lalu pindah ke Standard-IA, lalu ke Glacier, lalu dihapus setelah 365 hari.

<Box variant="exam" icon="🎯" label="Tips memilih jawaban">
  <p>
    Jika akses sering dan butuh cepat, pilih Standard. Jika pola akses tidak
    diketahui, pilih Intelligent-Tiering. Jika arsip sangat jarang diambil dan
    ingin biaya paling rendah, pilih Glacier Deep Archive.
  </p>
</Box>

</Section>

<Section num="09" id="s3-express-one-zone" title="S3 Express One Zone" sub="Storage class performa tinggi untuk workload sangat latency-sensitive">

<p class="lead">
  S3 Express One Zone adalah storage class S3 dengan performa tinggi dan latensi
  rendah untuk aplikasi yang sangat sering mengakses data dalam satu
  Availability Zone.
</p>

Kelas ini berbeda dari S3 Standard karena dirancang untuk akses data yang sangat cepat pada workload tertentu, misalnya analitik interaktif, machine learning, atau aplikasi yang perlu performa request sangat tinggi. Karena berada dalam satu Availability Zone, desainnya berbeda dari kelas multi-AZ seperti S3 Standard.

<CardGrid cols={2}>
  <Card>
    <h4>Kelebihan</h4>
    <p>
      Latency rendah dan performa tinggi untuk request yang intensif. Cocok saat
      aplikasi membutuhkan akses object sangat cepat.
    </p>
  </Card>
  <Card>
    <h4>Trade-off</h4>
    <p>
      Disimpan dalam satu Availability Zone, jadi pilihan ini perlu dipahami
      dari sisi risiko dan arsitektur high availability.
    </p>
  </Card>
</CardGrid>

<Box variant="exam" icon="🎯" label="Konteks ujian">
  <p>
    Jika soal menyebut kebutuhan latency sangat rendah untuk object storage
    dengan akses sangat sering, S3 Express One Zone bisa menjadi kandidat. Jika
    soal menekankan ketahanan multi-AZ umum, S3 Standard lebih lazim.
  </p>
</Box>

</Section>

<Section num="10" id="encryption-access-analyzer" title="Enkripsi dan IAM Access Analyzer" sub="Melindungi data dan mengecek akses eksternal">

<p class="lead">
  S3 mendukung enkripsi data saat tersimpan dan integrasi analisis akses untuk
  membantu menemukan bucket yang dapat diakses dari luar akun.
</p>

S3 encryption at rest dapat menggunakan beberapa pilihan. SSE-S3 memakai kunci yang dikelola S3. SSE-KMS memakai AWS KMS, sehingga ada kontrol kunci dan audit yang lebih kuat. SSE-C memakai kunci yang disediakan customer, tetapi lebih jarang dipakai pada skenario pemula.

<CardGrid cols={3}>
  <Card>
    <h4>SSE-S3</h4>
    <p>
      Enkripsi server-side dengan kunci yang dikelola S3. Mudah digunakan untuk
      banyak kebutuhan umum.
    </p>
  </Card>
  <Card>
    <h4>SSE-KMS</h4>
    <p>
      Enkripsi dengan AWS KMS. Cocok jika perlu kontrol kunci, audit, dan
      kebijakan KMS yang lebih ketat.
    </p>
  </Card>
  <Card>
    <h4>Client-side</h4>
    <p>
      Data dienkripsi oleh aplikasi sebelum dikirim ke S3. AWS menyimpan data
      yang sudah terenkripsi.
    </p>
  </Card>
</CardGrid>

<h3>IAM Access Analyzer for S3</h3>

IAM Access Analyzer dapat membantu mengidentifikasi bucket yang memiliki akses dari luar akun AWS. Ini berguna sebagai alat audit agar tim keamanan dapat melihat potensi akses publik atau cross-account yang tidak diinginkan.

<Box variant="tip" icon="🔍" label="Praktik baik">
  <p>
    Gunakan Block Public Access, enkripsi default, logging atau audit yang
    sesuai, dan review Access Analyzer secara rutin, terutama untuk bucket yang
    menyimpan data sensitif.
  </p>
</Box>

<Box variant="exam" icon="🎯" label="Ingat perbedaan">
  <p>
    Bucket policy mengatur akses. Encryption melindungi data saat tersimpan.
    Access Analyzer membantu menemukan akses eksternal yang mungkin tidak
    diinginkan.
  </p>
</Box>

</Section>

<Section num="11" id="shared-responsibility" title="Shared Responsibility Model untuk S3" sub="Mana tugas AWS, mana tugas customer">

<p class="lead">
  Dalam S3, AWS bertanggung jawab atas keamanan cloud, sedangkan customer
  bertanggung jawab atas keamanan data dan konfigurasi di dalam cloud.
</p>

AWS mengelola infrastruktur fisik, hardware, jaringan dasar, availability zone, dan layanan S3 itu sendiri. Customer mengelola bucket, object, IAM, bucket policy, enkripsi pilihan, klasifikasi data, lifecycle, logging, dan siapa yang boleh mengakses data.

<CardGrid cols={2}>
  <Card>
    <h4>Tanggung jawab AWS</h4>
    <p>
      Menjaga infrastruktur S3, durabilitas layanan, keamanan data center,
      hardware, dan operasional platform.
    </p>
  </Card>
  <Card>
    <h4>Tanggung jawab customer</h4>
    <p>
      Mengatur akses bucket, data classification, enkripsi, policy, versioning,
      lifecycle, backup strategi, dan pemantauan konfigurasi.
    </p>
  </Card>
</CardGrid>

<Box variant="warn" icon="⚠️" label="Kesalahan konsep">
  <p>
    Jika bucket tidak sengaja dibuat publik, itu biasanya tanggung jawab
    customer karena konfigurasi akses ada di sisi customer. AWS menyediakan alat
    pengaman, tetapi kita tetap harus menggunakannya dengan benar.
  </p>
</Box>

</Section>

<Section num="12" id="snow-family-storage-gateway" title="Snow Family dan Storage Gateway" sub="Menghubungkan data lokal dengan AWS storage">

<p class="lead">
  AWS Snow Family dan AWS Storage Gateway membantu saat data berada di luar AWS,
  terutama di data center, kantor cabang, lokasi edge, atau koneksi internet
  yang terbatas.
</p>

Snow Family adalah perangkat fisik untuk memindahkan data dalam jumlah besar atau menjalankan compute di lokasi edge. Storage Gateway adalah layanan hybrid cloud yang menghubungkan aplikasi on-premises dengan storage AWS seperti S3.

<CardGrid cols={2}>
  <Card>
    <h4>AWS Snowcone</h4>
    <p>
      Perangkat kecil untuk edge computing atau transfer data dalam ukuran lebih
      kecil, cocok untuk lokasi terbatas.
    </p>
  </Card>
  <Card>
    <h4>AWS Snowball Edge</h4>
    <p>
      Perangkat lebih besar untuk migrasi data massal dan beberapa workload edge
      compute. Sering muncul pada skenario transfer data besar.
    </p>
  </Card>
  <Card>
    <h4>AWS Snowmobile</h4>
    <p>
      Truk transfer data berskala sangat besar untuk migrasi ekstrem dalam
      ukuran exabyte.
    </p>
  </Card>
  <Card>
    <h4>AWS Storage Gateway</h4>
    <p>
      Menyediakan integrasi hybrid, misalnya file gateway agar aplikasi lokal
      dapat menyimpan file yang akhirnya berada di S3.
    </p>
  </Card>
</CardGrid>

<Box variant="analogy" icon="🚚" label="Analogi transfer">
  <p>
    Jika internet seperti jalan kecil dan data seperti ribuan kontainer,
    Snowball seperti mengirim truk fisik agar migrasi lebih cepat dan praktis
    daripada mengunggah semuanya lewat koneksi lambat.
  </p>
</Box>

<Box variant="exam" icon="🎯" label="Fokus ujian">
  <p>
    Jika pertanyaan menyebut transfer data sangat besar dengan internet lambat,
    pikirkan Snowball Edge atau Snow Family. Jika menyebut aplikasi on-premises
    yang perlu akses storage AWS secara hybrid, pikirkan Storage Gateway.
  </p>
</Box>

</Section>

<Section num="13" id="ringkasan" title="Ringkasan & Tips Ujian" sub="Poin yang paling perlu diingat">

<p class="lead">
  S3 adalah layanan inti AWS. Banyak layanan lain menyimpan log, backup,
  artifact, data lake, dan aset aplikasi di S3.
</p>

<Recap title="Poin Penting">
  <ul>
    <li>
      S3 adalah object storage, bukan block storage dan bukan file system
      tradisional.
    </li>
    <li>
      Bucket harus memiliki nama unik global dan dibuat di region tertentu.
    </li>
    <li>
      Object memiliki key, metadata, data, dan version ID jika versioning aktif.
    </li>
    <li>
      Block Public Access membantu mencegah bucket terbuka publik tanpa sengaja.
    </li>
    <li>
      Bucket policy melekat pada bucket, IAM policy melekat pada identitas.
    </li>
    <li>Pre-signed URL memberi akses sementara ke object private.</li>
    <li>
      Static website hosting cocok untuk HTML, CSS, JavaScript, dan aset statis,
      bukan backend server-side.
    </li>
    <li>
      Versioning membantu memulihkan object dari overwrite dan delete yang tidak
      disengaja.
    </li>
    <li>Replication membutuhkan versioning pada bucket sumber dan tujuan.</li>
    <li>
      Storage class dipilih berdasarkan pola akses, kebutuhan latency, dan
      biaya.
    </li>
    <li>
      Lifecycle rules membantu memindahkan data ke tier lebih murah atau
      menghapus data otomatis.
    </li>
    <li>
      SSE-S3 sederhana, SSE-KMS memberi kontrol dan audit kunci lebih kuat.
    </li>
    <li>
      Snow Family cocok untuk transfer data besar atau edge, Storage Gateway
      cocok untuk hybrid storage.
    </li>
  </ul>
</Recap>

<h3>Checklist cepat sebelum ujian</h3>

<CardGrid cols={2}>
  <Card>
    <h4>Jika soal bicara akses publik</h4>
    <p>
      Pikirkan Block Public Access, bucket policy, dan apakah data memang boleh
      publik.
    </p>
  </Card>
  <Card>
    <h4>Jika soal bicara akses sementara</h4>
    <p>
      Pikirkan pre-signed URL, terutama untuk object private yang hanya boleh
      diunduh dalam waktu terbatas.
    </p>
  </Card>
  <Card>
    <h4>Jika soal bicara arsip murah</h4>
    <p>
      Pikirkan keluarga Glacier, terutama Glacier Deep Archive untuk arsip
      jangka panjang yang jarang sekali dibuka.
    </p>
  </Card>
  <Card>
    <h4>Jika soal bicara data besar dari on-premises</h4>
    <p>
      Pikirkan Snowball Edge untuk transfer fisik, atau Storage Gateway untuk
      integrasi hybrid berkelanjutan.
    </p>
  </Card>
</CardGrid>

  <p>
    S3 adalah storage object yang sangat durable, scalable, aman bila
    dikonfigurasi benar, dan hemat biaya jika storage class serta lifecycle
    dipilih sesuai pola akses.
  </p>
</Box>
