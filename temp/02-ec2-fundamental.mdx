<Section num="01" id="budget" title="Atur Budget &amp; Alarm Biaya Dulu" sub="Pasang rem darurat sebelum mulai belajar">
<p class="lead">Sebelum menyentuh EC2, lakukan ini lebih dulu. Banyak pemula kaget melihat tagihan karena lupa mematikan instance. Kita pasang "rem darurat" supaya kamu belajar dengan tenang.</p>

<p>
  AWS punya layanan <strong>AWS Budgets</strong> yang bisa mengirim email
  peringatan saat pengeluaran mendekati batas yang kamu tentukan. Untuk belajar,
  target paling aman adalah tetap berada di dalam <strong>Free Tier</strong>{" "}
  (gratis 12 bulan pertama untuk layanan tertentu, termasuk EC2 tipe{" "}
  <code>t2.micro</code> / <code>t3.micro</code> selama 750 jam per bulan).
</p>

<Box variant="analogy" icon="💡" label="Analogi">
  <p>
    Budget itu seperti <strong>kuota internet di HP</strong>. Kamu tidak ingin
    tiba-tiba ditagih ratusan ribu karena lupa. Maka kamu set "kabari aku kalau
    sudah pakai 80%". AWS Budgets melakukan hal yang sama untuk uangmu.
  </p>
</Box>

<h3>Langkah singkat membuat budget</h3>
<Steps>
  <Step>
    <b>Buka Billing &amp; Cost Management</b>
    <p>Login ke AWS Console, ketik "Budgets" di kolom pencarian.</p>
  </Step>
  <Step>
    <b>Create budget &rarr; pilih "Zero spend" atau "Monthly cost"</b>
    <p>
      Untuk belajar, "Zero spend budget" akan memberi alarm begitu ada biaya
      sepeser pun keluar dari Free Tier.
    </p>
  </Step>
  <Step>
    <b>Tentukan ambang batas (threshold)</b>
    <p>
      Misalnya kabari di 50%, 80%, dan 100% dari target biaya bulanan (contoh:
      $5).
    </p>
  </Step>
  <Step>
    <b>Masukkan email penerima alarm</b>
    <p>Email kamu akan menerima notifikasi otomatis. Selesai.</p>
  </Step>
</Steps>

<Box variant="tip" icon="✓" label="Kebiasaan baik">
  <p>
    Setiap selesai latihan, <strong>Stop</strong> atau{" "}
    <strong>Terminate</strong> instance yang tidak dipakai. <em>Stop</em> =
    mematikan (bisa dinyalakan lagi, storage tetap dibayar tipis).{" "}
    <em>Terminate</em> = menghapus permanen (tidak ada biaya lagi).
  </p>
</Box>

<Recap title="Poin Penting">
<ul>
<li>Pasang AWS Budget + alarm email sebelum mulai praktik.</li>
<li>Pakai instance Free Tier (<code>t2.micro</code>/<code>t3.micro</code>) saat belajar.</li>
<li>Biasakan Terminate instance setelah selesai.</li>
</ul>
</Recap>
</Section>

<Section num="02" id="basics" title="EC2 Basics — Apa &amp; Kenapa" sub="Server virtual = IaaS, bayar sesuai pakai">
<p class="lead">EC2 adalah salah satu tawaran utama AWS dalam kategori <strong>IaaS (Infrastructure as a Service)</strong>. Sederhananya: kamu menyewa komputer milik Amazon, lewat internet, dan hanya membayar selama dipakai.</p>

<p>
  Sebagai React &amp; Laravel developer, bayangkan kamu selama ini menjalankan
  aplikasi Laravel di laptop lewat <code>php artisan serve</code>. EC2 memberimu
  komputer sungguhan di internet untuk menjalankan aplikasi itu agar bisa
  diakses orang lain &mdash; tanpa kamu harus membeli dan merawat server fisik.
</p>

<Box variant="analogy" icon="💡" label="Analogi: Sewa vs Beli Rumah">
  <p>
    Membeli server fisik = membeli rumah: mahal di depan, kamu urus listrik, AC,
    keamanan, perbaikan. <strong>EC2 = menyewa apartemen ber-furnitur</strong>:
    tinggal masuk, bayar bulanan/jam-an, kalau butuh lebih besar tinggal pindah
    unit, kalau tidak butuh tinggal keluar. Gedung &amp; infrastrukturnya diurus
    AWS.
  </p>
</Box>

<Figure>
  <EC2Fig01 />
  <Fragment slot="caption">
    <b>Bagaimana EC2 bekerja:</b> kamu mengakses lewat internet sebuah server
    virtual yang berjalan di atas server fisik AWS, di dalam sebuah Availability
    Zone, di dalam sebuah Region.
  </Fragment>
</Figure>

<h3>Apa saja yang bisa kamu atur saat membuat instance?</h3>
<p>
  Ketika "merakit" sebuah instance EC2, ada beberapa pilihan konfigurasi utama:
</p>
<ul class="clean">
  <li>
    <strong>OS (Sistem Operasi)</strong> &mdash; lewat <em class="term">AMI</em>
    : Linux (Amazon Linux, Ubuntu), Windows, atau macOS. (AMI dibahas detail di
    modul Storage.)
  </li>
  <li>
    <strong>CPU</strong> &mdash; berapa banyak inti prosesor / tenaga komputasi.
  </li>
  <li>
    <strong>RAM</strong> &mdash; berapa besar memori.
  </li>
  <li>
    <strong>Storage</strong> &mdash; penyimpanan disk (EBS / Instance Store
    &mdash; <em>dibahas terpisah</em>).
  </li>
  <li>
    <strong>Network</strong> &mdash; kecepatan kartu jaringan &amp; apakah punya
    Public IP.
  </li>
  <li>
    <strong>Security Group</strong> &mdash; aturan firewall (lihat Bagian 05).
  </li>
  <li>
    <strong>EC2 User Data</strong> &mdash; skrip otomatis yang dijalankan saat
    instance pertama kali menyala (lihat Bagian 03).
  </li>
</ul>

<Recap title="Poin Penting">
<ul>
<li>EC2 = menyewa server virtual = layanan <strong>IaaS</strong>.</li>
<li>Kamu mengontrol OS, CPU, RAM, storage, jaringan, firewall.</li>
<li>Bayar sesuai pemakaian (per detik/jam, tergantung tipe).</li>
</ul>
</Recap>
</Section>

<Section num="03" id="userdata" title="Hands-On: Membuat Instance + User Data" sub="Bootstrap server pertama dalam hitungan menit">
<p class="lead">Sekarang kita rakit instance pertama dan otomatis menjalankan sebuah website sederhana lewat <strong>EC2 User Data</strong>.</p>

<h3>Apa itu EC2 User Data?</h3>
<p>
  User Data adalah <strong>skrip yang dijalankan otomatis satu kali</strong>{" "}
  saat instance pertama kali boot. Ini cara untuk "bootstrapping" &mdash;
  menyiapkan server tanpa harus login manual: update paket, install software,
  jalankan service, dll.
</p>

<Box variant="warn" icon="!" label="Yang sering keluar di ujian">
  <p>
    User Data <strong>hanya berjalan sekali</strong> &mdash; yaitu pada{" "}
    <em>first boot</em>. Skrip dijalankan dengan hak akses <strong>root</strong>{" "}
    (jadi tidak perlu menulis <code>sudo</code>, walaupun banyak orang tetap
    menulisnya untuk kejelasan).
  </p>
</Box>

<h3>Langkah-langkah</h3>
<Steps>
  <Step>
    <b>Launch Instance</b>
    <p>
      Di EC2 Console klik <em>Launch instance</em>, beri nama (mis.
      "web-pertama").
    </p>
  </Step>
  <Step>
    <b>Pilih AMI &amp; tipe</b>
    <p>
      Pilih <em>Amazon Linux 2023</em> dan tipe <code>t2.micro</code> (Free Tier
      eligible).
    </p>
  </Step>
  <Step>
    <b>Buat Key Pair</b>
    <p>
      Buat key pair baru (mis. <code>belajar-aws.pem</code>) dan simpan
      baik-baik &mdash; dipakai untuk SSH nanti.
    </p>
  </Step>
  <Step>
    <b>Network settings</b>
    <p>
      Izinkan <em>HTTP (port 80)</em> dan <em>SSH (port 22)</em> di security
      group (lihat Bagian 05).
    </p>
  </Step>
  <Step>
    <b>Advanced details &rarr; User data</b>
    <p>Tempelkan skrip di bawah ini.</p>
  </Step>
  <Step>
    <b>Launch &amp; tunggu ~1 menit</b>
    <p>
      Salin <em>Public IPv4 address</em>, buka di browser. Website kamu sudah
      online!
    </p>
  </Step>
</Steps>

<span class="codetag">User Data — bash script</span>
<pre>
  <span class="c">#!/bin/bash</span>
  <span class="c"># update paket sistem</span>
  <span class="k">yum</span> update -y
  <span class="c"># install web server Apache</span>
  <span class="k">yum</span> install -y httpd
  <span class="c"># jalankan & aktifkan saat boot</span>
  <span class="k">systemctl</span> start httpd
  <span class="k">systemctl</span> enable httpd
  <span class="c"># buat halaman sederhana</span>
  <span class="k">echo</span>{" "}
  <span class="s">"&lt;h1&gt;Halo dari $(hostname -f)&lt;/h1&gt;"</span> &gt;
  /var/www/html/index.html
</pre>

<Box variant="tip" icon="✓" label="Cocok untuk dev Laravel">
  <p>
    Pola yang sama dipakai di dunia nyata untuk menyiapkan server PHP:{" "}
    <code>yum install -y php php-cli</code>, install Composer, lalu deploy
    aplikasi Laravel. User Data = "resep instalasi otomatis" server-mu.
  </p>
</Box>

<Recap title="Poin Penting">
<ul>
<li>User Data = skrip bootstrap, jalan <strong>sekali</strong> saat first boot, sebagai <strong>root</strong>.</li>
<li>Bisa untuk install &amp; konfigurasi software otomatis.</li>
<li>Buka port 80 (HTTP) agar website bisa diakses dari internet.</li>
</ul>
</Recap>
</Section>

<Section num="05" id="sg" title="Security Groups &amp; Classic Ports" sub="Firewall virtual yang mengelilingi instance EC2">
<p class="lead">Security Group adalah <strong>firewall virtual</strong> yang mengelilingi instance EC2 kamu. Ia mengatur lalu lintas mana yang boleh <em>masuk</em> (inbound) dan <em>keluar</em> (outbound).</p>

<h3>Karakter penting Security Group</h3>
<ul class="clean">
  <li>
    Hanya berisi aturan <strong>ALLOW</strong> (mengizinkan) &mdash; tidak ada
    aturan "deny". Apa pun yang tidak diizinkan, otomatis ditolak.
  </li>
  <li>
    Bisa mereferensikan <strong>IP/range</strong> atau bahkan{" "}
    <strong>Security Group lain</strong>.
  </li>
  <li>
    Satu Security Group bisa dipasang ke banyak instance, dan satu instance bisa
    punya banyak Security Group.
  </li>
  <li>
    Terikat pada <strong>Region + VPC</strong> tertentu (tidak otomatis terbawa
    ke region lain).
  </li>
  <li>
    Default: <strong>semua inbound diblokir</strong>,{" "}
    <strong>semua outbound diizinkan</strong>.
  </li>
</ul>

<Figure>
  <EC2Fig03 />
  <Fragment slot="caption">
    <b>Security Group sebagai penjaga gerbang.</b> Hanya port yang kamu izinkan
    yang bisa masuk; sisanya otomatis terblokir.
  </Fragment>
</Figure>

<Box variant="exam" icon="★" label="Trik ujian: timeout vs refused">
  <p>
    Kalau koneksi <strong>timeout</strong> (menggantung lalu gagal) &rarr;
    hampir pasti masalah <strong>Security Group</strong> (port tidak dibuka).
    Kalau <strong>"connection refused"</strong> &rarr; biasanya security group
    sudah benar, tapi <strong>aplikasi/service di server belum jalan</strong>.
  </p>
</Box>

<Recap title="Poin Penting">
<ul>
<li>Security Group = firewall instance, hanya aturan <strong>ALLOW</strong>.</li>
<li>Bisa pakai banyak SG per instance &amp; satu SG untuk banyak instance.</li>
<li>Hafal port: 22 SSH, 21 FTP, 80 HTTP, 443 HTTPS, 3389 RDP.</li>
<li>Timeout = masalah SG. Refused = masalah aplikasi.</li>
</ul>
</Recap>

<Section num="06" id="sg-hands" title="Hands-On: Mengatur Security Group" sub="Atur aturan inbound dengan benar dan aman">
<p class="lead">Mari atur aturan inbound dengan benar dan aman.</p>

<Steps>
  <Step>
    <b>Buka EC2 &rarr; Security Groups</b>
    <p>
      Pilih security group yang menempel di instance-mu, lalu tab{" "}
      <em>Inbound rules &rarr; Edit</em>.
    </p>
  </Step>
  <Step>
    <b>Tambah aturan HTTP</b>
    <p>
      Type: <em>HTTP</em>, Port: <code>80</code>, Source: <code>0.0.0.0/0</code>{" "}
      (semua orang boleh akses website).
    </p>
  </Step>
  <Step>
    <b>Tambah aturan SSH dengan aman</b>
    <p>
      Type: <em>SSH</em>, Port: <code>22</code>, Source: <strong>My IP</strong>{" "}
      (hanya alamat IP-mu). Hindari membuka <code>22</code> ke{" "}
      <code>0.0.0.0/0</code>.
    </p>
  </Step>
  <Step>
    <b>Simpan &amp; uji</b>
    <p>Refresh website di browser; coba SSH (Bagian 07).</p>
  </Step>
</Steps>

<Box variant="warn" icon="!" label="Praktik aman">
  <p>
    Membuka SSH (port 22) ke seluruh dunia (<code>0.0.0.0/0</code>) berbahaya
    &mdash; bot di internet terus mencoba menebak akses. Selalu batasi SSH ke{" "}
    <strong>My IP</strong> saja.
  </p>
</Box>

<Recap title="Poin Penting">
<ul>
<li>HTTP/HTTPS untuk publik (<code>0.0.0.0/0</code>) tidak masalah.</li>
<li>SSH/RDP sebaiknya dibatasi ke <strong>My IP</strong>.</li>
</ul>
</Recap>
</Section>

<Section num="07" id="ssh" title="SSH — Masuk ke Dalam Server" sub="Login remote terenkripsi via port 22 + key pair">
<p class="lead"><strong>SSH (Secure Shell)</strong> adalah cara untuk login dan mengendalikan server Linux dari jarak jauh, lewat terminal, secara terenkripsi. Ini menggunakan port <code>22</code> dan sebuah pasangan kunci (key pair).</p>

<h3>Konsep Key Pair (kunci publik &amp; privat)</h3>
<Figure>
  <EC2Fig04 />
  <Fragment slot="caption">
    <b>Cara kerja key pair:</b> AWS menaruh <i>public key</i> di server; kamu
    menyimpan <i>private key</i> (.pem). Keduanya cocok &rarr; kamu boleh masuk.
    Tanpa private key, tidak ada yang bisa login.
  </Fragment>
</Figure>

<h3>SSH dari Linux / macOS</h3>
<span class="codetag">Terminal — Linux / macOS</span>
<pre>
  <span class="c"># amankan permission file kunci (WAJIB, sekali saja)</span>
  <span class="k">chmod</span> 400 belajar-aws.pem
  <span class="c"># login ke instance (user Amazon Linux = ec2-user)</span>
  <span class="k">ssh</span> -i belajar-aws.pem ec2-user@
  <span class="o">&lt;Public-IPv4&gt;</span>
</pre>
<p>
  Username default berbeda tergantung OS: Amazon Linux = <code>ec2-user</code>,
  Ubuntu = <code>ubuntu</code>, CentOS = <code>centos</code>.
</p>

<h3>SSH dari Windows</h3>
<h4>Windows 10/11 (cara modern &mdash; direkomendasikan)</h4>
<p>
  Windows 10 ke atas sudah punya OpenSSH bawaan. Buka{" "}
  <strong>PowerShell / Command Prompt</strong> dan jalankan perintah{" "}
  <code>ssh</code> yang persis sama seperti di Linux/Mac di atas. Untuk
  permission file <code>.pem</code>, atur lewat Properties &rarr; Security, atau
  perintah <code>icacls</code>.
</p>
<h4>Windows lama (cara klasik &mdash; PuTTY)</h4>
<ul class="clean">
  <li>
    Install <strong>PuTTY</strong> dan <strong>PuTTYgen</strong>.
  </li>
  <li>
    Pakai PuTTYgen untuk mengubah file <code>.pem</code> menjadi{" "}
    <code>.ppk</code>.
  </li>
  <li>
    Di PuTTY: isi <em>Host Name</em> = <code>ec2-user@&lt;Public-IP&gt;</code>,
    lalu di <em>Connection &rarr; SSH &rarr; Auth</em> pilih file{" "}
    <code>.ppk</code>-mu.
  </li>
</ul>

<Recap title="Poin Penting">
<ul>
<li>SSH = login remote terenkripsi via port <strong>22</strong> + key pair.</li>
<li>Private key (.pem) bersifat rahasia; jangan pernah dibagikan.</li>
<li>Windows modern: pakai <code>ssh</code> bawaan. Windows lama: PuTTY (.ppk).</li>
</ul>
</Recap>
</Section>

<Section num="08" id="ssh-trouble" title="SSH Troubleshooting" sub="Empat masalah umum dan cara mengatasinya">
<p class="lead">Empat masalah ini mencakup hampir semua kegagalan SSH yang dialami pemula.</p>

<div class="tbl-wrap">
  <table>
    <thead>
      <tr>
        <th>Gejala</th>
        <th>Penyebab umum</th>
        <th>Solusi</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td>
          <strong>Connection timed out</strong>
        </td>
        <td>
          Port 22 tidak dibuka / Security Group salah / instance bukan public
        </td>
        <td>
          Tambah aturan SSH (22) ke Security Group; pastikan instance punya
          Public IP
        </td>
      </tr>
      <tr>
        <td>
          <strong>Permission denied (publickey)</strong>
        </td>
        <td>Salah key pair, atau salah username</td>
        <td>
          Pakai .pem yang benar; gunakan user yang sesuai OS (
          <code>ec2-user</code>, <code>ubuntu</code>)
        </td>
      </tr>
      <tr>
        <td>
          <strong>Unprotected private key file</strong>
        </td>
        <td>Permission file .pem terlalu terbuka</td>
        <td>
          Jalankan <code>chmod 400 file.pem</code> (atau <code>icacls</code> di
          Windows)
        </td>
      </tr>
      <tr>
        <td>
          <strong>Connection refused</strong>
        </td>
        <td>Service SSH belum jalan / instance baru saja restart</td>
        <td>Tunggu instance siap, atau reboot instance</td>
      </tr>
    </tbody>
  </table>
</div>

<Box variant="exam" icon="★" label="Ingat pola ini">
<p><strong>Timeout &rarr; Security Group.</strong> <strong>Permission denied &rarr; key/username.</strong> Dua kalimat ini menyelamatkanmu di ujian maupun di pekerjaan nyata.</p>
</Box>
</Section>

<Section num="09" id="connect" title="EC2 Instance Connect" sub="Akses terminal langsung dari browser AWS Console">
<p class="lead">Tidak punya file <code>.pem</code> di depanmu? <strong>EC2 Instance Connect</strong> membuatmu bisa masuk ke instance langsung dari <strong>browser</strong>, lewat AWS Console &mdash; tanpa repot mengelola kunci.</p>

<p>
  Cara kerjanya: saat kamu klik "Connect", AWS{" "}
  <strong>menyuntikkan kunci SSH sementara</strong> ke instance untuk waktu yang
  sangat singkat, lalu membuka sesi terminal di tab browser. Praktis untuk akses
  cepat.
</p>

<Box variant="warn" icon="!" label="Catatan penting">
  <p>
    EC2 Instance Connect <strong>tetap memakai port 22 (SSH)</strong> di balik
    layar. Jadi Security Group kamu{" "}
    <strong>tetap harus mengizinkan port 22</strong> &mdash; dan idealnya dari
    rentang IP AWS. Ini paling mudah dipakai pada Amazon Linux 2 / 2023.
  </p>
</Box>

<Figure>
  <EC2Fig05 />
  <Fragment slot="caption">
    <b>EC2 Instance Connect:</b> akses lewat browser, AWS yang mengurus kunci
    sementara &mdash; port 22 tetap diperlukan.
  </Fragment>
</Figure>

<Recap title="Poin Penting">
<ul>
<li>Connect via browser, tanpa mengelola .pem sendiri.</li>
<li>Tetap butuh <strong>port 22</strong> terbuka di Security Group.</li>
</ul>
</Recap>
</Section>

<Section num="10" id="roles" title="EC2 Instance Roles (IAM Role)" sub="Beri izin ke instance tanpa menyimpan access key">
<p class="lead">Kalau aplikasi di instance perlu mengakses layanan AWS lain (misal membaca file di S3), <strong>JANGAN</strong> menyimpan access key di dalam server. Pakai <strong>IAM Role</strong> yang dipasang ke instance.</p>

<Box variant="warn" icon="!" label="Kesalahan fatal yang sering terjadi">
  <p>
    Menaruh <code>AWS_ACCESS_KEY_ID</code> dan secret key di dalam file{" "}
    <code>.env</code> Laravel di server EC2 = sangat berbahaya. Jika server
    dibobol, kredensialmu ikut bocor. Gunakan IAM Role sebagai gantinya.
  </p>
</Box>

<Figure>
  <EC2Fig06 />
  <Fragment slot="caption">
    <b>IAM Role pada EC2:</b> instance mendapat izin sementara yang dirotasi
    otomatis oleh AWS. Tidak ada kredensial yang disimpan manual.
  </Fragment>
</Figure>

<h3>Demo singkat</h3>
<Steps>
  <Step>
    <b>Buat IAM Role</b>
    <p>
      Di IAM Console &rarr; Roles &rarr; Create role &rarr; pilih <em>EC2</em>{" "}
      sebagai trusted entity, lalu lampirkan policy (mis.{" "}
      <code>AmazonS3ReadOnlyAccess</code>).
    </p>
  </Step>
  <Step>
    <b>Pasang ke instance</b>
    <p>
      Di EC2 &rarr; pilih instance &rarr; Actions &rarr; Security &rarr;{" "}
      <em>Modify IAM role</em> &rarr; pilih role tadi.
    </p>
  </Step>
  <Step>
    <b>Selesai</b>
    <p>
      Aplikasi/SDK di dalam instance otomatis bisa pakai izin itu tanpa
      kredensial tersimpan.
    </p>
  </Step>
</Steps>

<Recap title="Poin Penting">
<ul>
<li>EC2 mengakses layanan AWS lain lewat <strong>IAM Role</strong>, bukan access key.</li>
<li>Kredensial bersifat sementara &amp; dirotasi otomatis = lebih aman.</li>
<li>Satu instance hanya bisa memiliki satu IAM Role aktif pada satu waktu.</li>
</ul>
</Recap>
</Section>

<Section num="11" id="purchasing" title="EC2 Instance Purchasing Options" sub="Pilih opsi bayar yang tepat, hemat hingga 90%">
<p class="lead">Ada banyak cara membayar EC2. Memilih yang tepat bisa menghemat biaya hingga <strong>90%</strong>. Ini topik favorit di ujian &mdash; pahami trade-off masing-masing.</p>

<Figure>
  <EC2Fig07 />
  <Fragment slot="caption">
    <b>Spektrum biaya EC2:</b> dari kiri (fleksibel tapi mahal) ke kanan (murah
    tapi butuh komitmen / punya syarat).
  </Fragment>
</Figure>

<div class="tbl-wrap">
  <table>
    <thead>
      <tr>
        <th>Opsi</th>
        <th>Inti</th>
        <th>Kapan dipakai</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td>
          <strong>On-Demand</strong>
        </td>
        <td>Bayar sesuai pakai, tanpa komitmen, harga tertinggi</td>
        <td>Aplikasi baru/uji coba, beban tak terprediksi, jangka pendek</td>
      </tr>
      <tr>
        <td>
          <strong>Reserved Instances</strong>
        </td>
        <td>Komitmen 1 atau 3 tahun (Standard / Convertible), diskon besar</td>

        <td>
          <strong>Savings Plans</strong>

    besar. <strong>Spot</strong> = kamar sisa harga obral, tapi bisa diminta

<li><strong>Spot</strong>: termurah (s/d 90%), tapi bisa dicabut &mdash; untuk workload tahan gangguan.</li>

<Section num="12" id="shared" title="Shared Responsibility Model untuk EC2" sub="AWS amankan infrastruktur, kamu amankan konfigurasi">
<p class="lead">Konsep yang <strong>pasti</strong> muncul di ujian. Keamanan di AWS adalah tanggung jawab bersama: AWS mengamankan <em>cloud-nya</em>, kamu mengamankan apa yang kamu <em>taruh di dalam</em> cloud.</p>

<Figure>
  <EC2Fig08 />
  <Fragment slot="caption">
    <b>Pembagian tanggung jawab:</b> AWS mengurus "rumah &amp; gedungnya", kamu
    mengurus "isi &amp; kunci pintunya".
  </Fragment>
</Figure>

<Box variant="exam" icon="★" label="Cara cepat menjawab">
<p>Jika soal menyebut <strong>patch OS, firewall/Security Group, IAM, data, atau aplikasi</strong> &rarr; itu <strong>tanggung jawab kamu</strong>. Jika menyebut <strong>hardware, data center, hypervisor, jaringan fisik</strong> &rarr; itu <strong>tanggung jawab AWS</strong>.</p>
</Box>
</Section>
