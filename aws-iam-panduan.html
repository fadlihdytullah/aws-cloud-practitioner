01

Apa itu IAM?

Identity and Access Management — Users, Groups, dan Policies

IAM (Identity and Access Management) adalah layanan AWS untuk mengatur identitas (siapa) dan izin akses (boleh melakukan apa) di dalam akun AWS Anda. Singkatnya: IAM menentukan siapa boleh masuk dan apa yang boleh mereka lakukan.

Saat pertama membuat akun AWS, Anda mendapat satu identitas super-kuat bernama Root User. Root bisa melakukan segalanya tanpa batas — dan justru karena itu sangat berbahaya jika sampai jatuh ke tangan yang salah. Karena itu, root sebaiknya hampir tidak pernah dipakai untuk pekerjaan harian.

🏢 Analogi

Bayangkan akun AWS Anda adalah sebuah gedung kantor. Root user adalah pemilik gedung yang punya kunci master ke semua ruangan — sangat berbahaya kalau hilang. IAM Users adalah karyawan dengan kartu akses masing-masing. Groups adalah divisi (Finance, Developer, HR). Policies adalah aturan tertulis: "Divisi Finance boleh masuk ruang brankas, tapi tidak boleh masuk ruang server."

Tiga konsep inti yang akan kita pakai berulang kali:

User

Satu identitas untuk satu orang nyata (misalnya: Andi, Budi). Setiap orang sebaiknya punya user IAM sendiri.

Group

Kumpulan user. Group hanya bisa berisi user — tidak bisa berisi group lain. Satu user bisa masuk ke beberapa group, atau tidak masuk group sama sekali.

Policy

Dokumen (format JSON) yang mendefinisikan izin: layanan apa yang boleh/tidak boleh diakses dan tindakan apa yang boleh dilakukan. Policy bisa ditempel ke User maupun Group.

02

IAM Users & Groups

Membuat identitas untuk setiap orang dan mengelompokkannya

Praktik yang benar: buat satu IAM user untuk setiap orang, lalu masukkan ke group sesuai perannya. Jangan pernah berbagi satu user untuk banyak orang, dan jangan pakai root untuk tugas sehari-hari.

Kenapa pakai group? Karena menempelkan policy ke group jauh lebih mudah dikelola daripada ke tiap user satu per satu. Kalau ada developer baru, cukup masukkan dia ke group "Developers" — dia otomatis dapat semua izin yang dibutuhkan.

Langkah membuat User & Group (di Console)

Buka layanan IAM

Cari "IAM" di kotak pencarian AWS Console. IAM adalah global service — tidak terikat region tertentu.

Buat Group lebih dulu

Menu User groups → Create group. Beri nama (mis. "Admins"), lalu tempelkan policy seperti AdministratorAccess.

Buat User

Menu Users → Create user. Beri nama, lalu pilih akses: Console (login lewat browser) dan/atau programmatic (lewat kode/CLI).

Masukkan ke Group

Saat membuat user, pilih group yang sudah dibuat. User langsung mewarisi semua izin group tersebut.

Catat Account ID / alias

User IAM login lewat URL khusus yang berisi Account ID 12 digit. Anda bisa membuat account alias agar URL-nya lebih mudah diingat.

💡 Tips

Ada dua cara seseorang login: Root user login dengan email + password akun. IAM user login lewat halaman khusus dengan Account ID + username + password. Pastikan Anda berbagi link login IAM yang benar ke tim Anda.

03

IAM Policies

Anatomi dokumen izin berformat JSON

Policy adalah dokumen JSON yang berisi daftar izin. Inilah "aturan main" yang menentukan apa yang boleh dan tidak boleh dilakukan sebuah identitas. Memahami strukturnya penting karena Anda akan sering membacanya.

Prinsip kunci: jika user ada di sebuah group, ia mewarisi policy group itu. Ia juga bisa punya inline policy yang menempel langsung ke dirinya saja. Total izin = gabungan semua policy yang berlaku.

Anatomi sebuah policy

ElemenFungsi
VersionVersi bahasa policy. Hampir selalu 2012-10-17.
Id (opsional)Pengenal untuk policy tersebut.
StatementInti dari policy — berisi satu atau lebih aturan izin.
EffectAllow (mengizinkan) atau Deny (melarang). Deny selalu menang jika bentrok.
ActionDaftar tindakan, mis. s3:GetObject, ec2:StartInstances.
ResourceSumber daya yang dikenai aturan, ditulis sebagai ARN (Amazon Resource Name).
Condition (opsional)Syarat tambahan kapan aturan berlaku (mis. hanya dari IP tertentu).
🔑 Analogi

Anggap policy seperti daftar izin di kartu akses karyawan: Effect = boleh/tidak boleh, Action = aktivitas (buka pintu, nyalakan AC), Resource = ruangan mana. "Boleh (Allow) membuka pintu (Action) ruang 3A (Resource)."

AWS sudah menyediakan banyak managed policy bawaan (seperti AdministratorAccess atau ReadOnlyAccess) yang bisa langsung dipakai tanpa menulis JSON sendiri. Anda juga bisa menggunakan Visual Editor di console untuk membuat policy tanpa mengetik JSON manual.

04

Login Bersamaan di Console

Beberapa identitas bisa masuk di waktu yang sama

Anda bisa login ke AWS Console dengan lebih dari satu identitas sekaligus di satu browser. Caranya menggunakan fitur multi-session bawaan AWS Console, atau cara klasik: pakai jendela incognito/private untuk sesi terpisah.

Ini berguna saat Anda ingin, misalnya, membandingkan apa yang dilihat seorang admin versus seorang user biasa dengan izin terbatas — tanpa harus logout-login berulang kali. Cara ini sangat membantu ketika sedang menguji apakah policy yang Anda buat sudah benar.

💡 Praktik

Saat belajar policy, login sebagai user terbatas di jendela incognito untuk melihat secara langsung mana yang ter-blokir (muncul pesan "not authorized") dan mana yang diizinkan. Ini cara tercepat memahami efek sebuah policy.

05

MFA — Multi-Factor Authentication

Lapisan keamanan kedua selain password

MFA menambahkan lapisan keamanan kedua. Selain sesuatu yang Anda tahu (password), Anda juga butuh sesuatu yang Anda miliki (perangkat MFA, biasanya HP). Jadi meskipun password bocor, penyerang tetap tidak bisa masuk tanpa perangkat Anda.

Jenis perangkat MFA di AWS

Virtual MFA

Aplikasi di HP seperti Google Authenticator atau Authy. Paling umum & gratis. Bisa untuk banyak akun.

Security Key (FIDO)

Perangkat fisik USB seperti YubiKey. Anda tinggal colok & sentuh untuk verifikasi.

Hardware TOTP Token

Alat khusus yang menampilkan kode berganti tiap 30 detik (mis. perangkat dari Thales/Gemalto).

Hardware untuk AWS GovCloud

Token fisik khusus untuk lingkungan pemerintah AS (kasus khusus).

⚠️ Penting

Yang paling utama adalah mengaktifkan MFA pada Root user dan akun-akun admin. Ini langkah keamanan nomor satu yang harus Anda lakukan segera setelah membuat akun AWS.

06

Access Keys, CLI & SDK

Tiga cara berbeda mengakses AWS

Ada tiga jalur untuk berinteraksi dengan AWS. Memahami perbedaannya membantu Anda memilih alat yang tepat:

AWS CLI (Command Line Interface)

Alat untuk mengendalikan AWS lewat perintah teks di terminal. Cocok untuk otomatisasi dan scripting. Open-source.

AWS SDK (Software Development Kit)

Library untuk memanggil AWS dari dalam kode program Anda (tersedia untuk Python/boto3, JavaScript, Java, Go, dan banyak bahasa lain).

Access Keys

Sepasang kredensial — Access Key ID (seperti username) dan Secret Access Key (seperti password) — yang dipakai CLI dan SDK untuk login. Dibuat di console oleh masing-masing user.

⚠️ Jangan sampai bocor

Access keys adalah rahasia — perlakukan seperti password. Jangan pernah membagikannya, jangan menulisnya ke kode yang di-upload ke GitHub, dan jangan menampilkannya di screenshot. Secret access key hanya bisa dilihat satu kali saat dibuat.

07

Memasang AWS CLI

Windows, macOS, dan Linux

Cara pemasangan sedikit berbeda tiap sistem operasi, tapi cara konfigurasinya sama. Setelah terpasang, jalankan aws --version untuk memastikan berhasil.

🪟 Windows

Unduh installer .msi resmi dari AWS, lalu jalankan seperti aplikasi biasa (klik next-next-finish).

🍎 macOS

Unduh paket .pkg resmi dari AWS dan instal, atau gunakan installer baris perintah.

🐧 Linux

Unduh file zip resmi, ekstrak, lalu jalankan skrip install yang disertakan.

Konfigurasi (sama di semua OS)

Setelah CLI terpasang, hubungkan dengan akun Anda menggunakan access keys:

aws configure
# lalu masukkan satu per satu:
AWS Access Key ID     : AKIA****************
AWS Secret Access Key : ****************************************
Default region name   : ap-southeast-1   # mis. Singapura
Default output format : json

Mencoba perintah pertama

aws iam list-users          # tampilkan semua IAM user
aws sts get-caller-identity  # cek "saya login sebagai siapa?"
💡 Tips

Perintah aws sts get-caller-identity sangat berguna untuk memastikan CLI Anda benar-benar terhubung dan login sebagai identitas yang Anda kira.

08

AWS CloudShell

Terminal siap pakai langsung di browser

CloudShell adalah terminal berbasis browser yang sudah terpasang AWS CLI dan otomatis login dengan kredensial Anda. Tidak perlu install apa pun, tidak perlu set access keys — tinggal klik ikonnya di pojok atas console dan langsung bisa menjalankan perintah AWS.

✅ Kelebihan

Tanpa instalasi, kredensial otomatis, punya penyimpanan persisten kecil, bisa upload/download file. Ideal untuk pemula.

📍 Catatan

CloudShell tidak tersedia di semua region, dan tetap memakai izin (policy) IAM user/role yang sedang Anda pakai.

☁️ Analogi

Kalau AWS CLI di laptop seperti membawa peralatan sendiri, maka CloudShell seperti menyewa bengkel lengkap yang sudah ada semua alatnya — Anda tinggal datang dan bekerja.

09

IAM Roles untuk AWS Services

Memberi izin pada layanan, bukan orang

Sejauh ini izin kita berikan ke orang (user). Tapi seringkali layanan AWS sendiri perlu izin untuk bekerja. Contoh: sebuah server EC2 perlu membaca file dari S3. Server bukan manusia — ia tidak bisa mengetik password atau menyimpan access keys dengan aman.

Solusinya: IAM Role. Role mirip user (punya policy), tapi dirancang untuk "dipinjam" (assumed) oleh layanan AWS, bukan dipakai login oleh orang. Kredensialnya bersifat sementara dan dikelola otomatis oleh AWS.

Layanan yang umum memakai role antara lain: EC2 Instances, Lambda Functions, dan layanan otomasi seperti CloudFormation. Anda membuat role, menentukan layanan apa yang boleh memakainya, lalu menempelkan policy izin yang dibutuhkan.

💡 Intinya

Role = identitas untuk mesin/layanan. Selalu pilih role daripada menanam access keys di dalam kode atau server — lebih aman karena kredensialnya sementara dan dikelola otomatis.

10

IAM Security Tools

Dua alat untuk audit keamanan

IAM punya dua alat bawaan untuk membantu Anda memeriksa kesehatan keamanan akun:

Credentials Report

Laporan tingkat akun. Daftar semua user beserta status kredensialnya: kapan password terakhir diganti, apakah MFA aktif, kapan access key terakhir dipakai. Bisa diunduh sebagai CSV.

Access Advisor

Laporan tingkat user. Menunjukkan layanan apa saja yang punya izin dan kapan terakhir benar-benar diakses. Sangat berguna untuk menemukan dan mencabut izin yang tidak terpakai.

💡 Manfaat

Gunakan Access Advisor untuk menerapkan prinsip least privilege: kalau ada izin yang tidak pernah dipakai selama berbulan-bulan, kemungkinan besar memang tidak perlu — dan sebaiknya dicabut.

11

IAM Best Practices

Aturan emas yang wajib diikuti

🚫 Jangan pakai Root

Root user hanya untuk setup awal akun. Untuk semua hal lain, gunakan IAM user.

👤 Satu user satu orang

Jangan berbagi akun. Setiap orang punya IAM user sendiri.

👥 Tempel policy ke Group

Kelola izin lewat group, bukan ke tiap user satu-satu.

🔐 Wajibkan password kuat

Terapkan password policy (panjang minimum, kombinasi karakter).

📱 Aktifkan MFA

Terutama untuk root dan semua akun penting.

🎭 Pakai Role untuk layanan

Beri izin EC2/Lambda lewat role, bukan access keys.

🔑 Jaga Access Keys

Jangan share, jangan commit ke repo, rotasi berkala.

📊 Audit rutin

Gunakan Credentials Report & Access Advisor secara berkala.

🎯 Prinsip utama

Least Privilege (hak akses seminimal mungkin). Beri setiap orang/layanan hanya izin yang benar-benar dibutuhkan untuk tugasnya — tidak lebih. Ini meminimalkan kerusakan jika satu akun disusupi.

12

Shared Responsibility Model

Siapa bertanggung jawab atas apa

Keamanan di AWS adalah tanggung jawab bersama. AWS mengamankan infrastruktur-nya, sementara Anda bertanggung jawab atas cara Anda menggunakannya. Untuk IAM, pembagiannya jelas:

Kesimpulan sederhananya: AWS menyediakan alat keamanan yang andal, tapi memakainya dengan benar adalah tugas Anda. Kebanyakan insiden keamanan terjadi karena kesalahan konfigurasi di sisi pelanggan — misalnya access key bocor atau policy yang terlalu longgar.

13

Ringkasan

Poin-poin kunci yang harus diingat

🎯 Yang perlu Anda kuasai dari modul IAM

  • Users = orang. Groups = kumpulan user. Policies = dokumen JSON berisi izin.
  • Root user hanya untuk setup awal — jangan dipakai sehari-hari.
  • Tempelkan policy ke group, bukan ke tiap user, agar mudah dikelola.
  • Aktifkan MFA (lapisan kedua: password + perangkat) terutama untuk root.
  • Tiga cara akses AWS: Console (browser), CLI (terminal), SDK (kode). CLI & SDK butuh Access Keys — jaga kerahasiaannya.
  • CloudShell = terminal siap pakai di browser, tanpa instalasi & konfigurasi.
  • IAM Roles memberi izin pada layanan (EC2, Lambda) — bukan orang.
  • Audit dengan Credentials Report (level akun) & Access Advisor (level user).
  • Pegang prinsip least privilege — beri izin seminimal yang dibutuhkan.
  • Shared Responsibility: AWS amankan infrastruktur, Anda amankan konfigurasi & penggunaan.
▶️ Langkah selanjutnya

Setelah memahami IAM, lanjutkan ke modul EC2 (server virtual) — di sana Anda akan langsung mempraktikkan IAM Roles untuk pertama kalinya. IAM adalah fondasi yang akan terus Anda pakai di semua layanan AWS lainnya.
